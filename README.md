# Hörmann SupraMatic E (Serie 4) BLE → Home Assistant

Управление приводом ворот Hörmann SupraMatic E (BlueSecur BLE) через Home
Assistant по Wi-Fi/MQTT, без проводов и без пайки — плата Seeed XIAO
ESP32-C3 сама регистрируется как дополнительный "пользователь" привода и
шлёт подписанные команды.

Протокол **нигде публично не документирован** — восстановлен с нуля методом
BLE-сниффинга (nRF52840 + nRF Sniffer for Bluetooth LE) и декомпиляции
официального Android-приложения BlueSecur (.NET MAUI / Xamarin, через
AssemblyStore → ilspycmd → C#).

## Железо

- Hörmann SupraMatic E, серия 4 (артикул 4510314)
- Seeed XIAO ESP32-C3 (прошивка в `esp32/`)
- nRF52840 Dongle с прошивкой "nRF Sniffer for Bluetooth LE" — нужен только
  для исследования/отладки, не для повседневной работы

## Протокол (кратко)

BLE GATT-сервис `669a9001-0008-968f-e311-6050405558b3`:
- `669a900a-...` — notify-характеристика (уведомления устройства)
- `669a900c-...` — write-характеристика (команды)

**Регистрация нового ключа (один раз, пока привод в режиме привязки):**
1. Приложение генерирует случайный 32-байтный ключ.
2. Шифрует его RSA (PKCS#1 v1.5) публичным ключом привода — публичный ключ
   закодирован в Base64-хвосте **QR-кода на корпусе привода** (формат QR
   описан в `research/qr_parser.py`). Полностью офлайн, без сервера.
3. Шлёт зашифрованный блок в write-характеристику: `[0x02][len16][RSA-блок]`,
   кусками по 20 байт.
4. Устройство шлёт прогресс-уведомления `[0x02][0x04][0x00][шаг]` — шаг
   **обязательно должен дойти до 2** (не просто "дошло до какого-то шага").
5. В момент шага=2 — **сразу**, без ожидания отдельного сигнала — шлётся
   подписанная команда `RegisterRoot` (см. ниже), подписанная **тем же
   случайным ключом**, который только что сгенерировали, с challenge,
   полученным **в начале соединения** (не позже).
6. Успешный ответ — notify-уведомление типа `ROOT_KEY` (60 байт), несущее:
   `[8-байт challenge][2-байт type=2][2-байт ...][2-байт RootId][32-байт
   XOR-замаскированный ключ]`. **Финальный рабочий ключ = эти 32 байта XOR
   наш исходный ключ.** Именно он (не исходный!) используется для всех
   дальнейших команд, вместе с присвоенным RootId (НЕ обязательно 0 — у нас
   было `1`, т.к. `0` уже занят ключом телефона).

**Обычная подписанная команда** (после регистрации):
```
HMAC-SHA256(key, data = [RootId16][Command16][Length16][payload] || challenge8)
```
где `challenge` — 8-байтное значение из последнего notify-уведомления
устройства (rolling-токен, меняется после каждой успешной команды).
Структура уведомлений: `[1][len16][challenge8][SignedNotificationType16][...]`.

**Коды каналов** (низкие 16 бит `DeviceAction` из декомпилированного enum),
определены эмпирически нажатием каждой кнопки и наблюдением за воротами:

| Канал | Hex | Функция |
|---|---|---|
| CHANNEL_1 | 0x11 | Impuls (универсальный импульс открыть/стоп/закрыть) |
| CHANNEL_2 | 0x12 | Свет |
| CHANNEL_3 | 0x13 | 1/2 — частичное открытие |
| CHANNEL_4 | 0x14 | Открыть |
| CHANNEL_5 | 0x15 | Закрыть |
| CHANNEL_6 | 0x16 | Положение проветривания (маленькая щель) |

## Важные грабли (сэкономит часы, если повторять)

1. **Нестабильное окно регистрации.** Даже официальное приложение иногда не
   проходит регистрацию с первой попытки (подтверждено сравнительным
   сниффингом — первое подключение реального телефона тоже иногда
   "зависает" на шаге прогресса и просто переподключается заново, без
   перезагрузки привода). Наш код (`toggle_light.py`, `main.cpp`)
   автоматически переподключается при неудаче — это нормально, не баг.
2. **Если совсем не проходит** (несколько переподключений подряд без
   прогресса) — помогает **полный перезапуск привода по питанию** (не
   только BLE-сброс через меню).
3. **Меню 19 → 02 (BLE) → P → кнопка Bluetooth на корпусе** открывает окно
   привязки, сбрасывая именно BLE-ключи, не трогая настройки ворот.
   **НЕ путать с меню 37 (Werksreset)** — это сбрасывает концевые положения,
   усилия и тип ворот (пришлось заново проходить обучение хода после
   ошибочного использования этого пункта).
4. На Windows (`bleak`/WinRT) запись может кидать `WinError -2147023673`
   ("operation canceled") даже когда данные реально дошли — это
   спурионная ошибка стека, нужно игнорировать и просто слать следующий
   кусок (см. `write_chunks` в `toggle_light.py`).
5. На ESP32 (NimBLE) **обязательно** выносить длинную регистрацию из MQTT
   callback в основной `loop()` — иначе плата перезагружается
   (watchdog/стек) во время долгого ожидания.
6. Критичный баг, на поиск которого ушло больше всего времени: **подпись
   `RegisterRoot` должна использовать СВЕЖЕСГЕНЕРИРОВАННЫЙ ключ, а не
   текущий сохранённый `gRootKey`** (который на момент первой регистрации
   ещё пустой). Проверять это в первую очередь при похожих симптомах
   (стабильный `SECURITY_ERROR` на каждой первой попытке).

## Структура репозитория

- `esp32/` — прошивка PlatformIO (Arduino framework, NimBLE-Arduino,
  mbedTLS для RSA/HMAC, PubSubClient для MQTT с Home Assistant discovery).
  `gen_secrets.py` — pre-build скрипт, читает локальные секреты (ниже) и
  генерирует `include/secrets_generated.h` (не коммитится).
- `research/` — Python-скрипты, которыми восстанавливали протокол и
  проверяли гипотезы на ПК через `bleak`:
  - `qr_parser.py` — разбор QR-кода привода (версии 1-4).
  - `extract_xaba.py` — распаковка .NET MAUI AssemblyStore (формат XABA) из
    APK приложения BlueSecur, для последующей декомпиляции через `ilspycmd`.
  - `toggle_light.py` — финальный рабочий PoC: регистрация ключа + отправка
    команд с ПК (без платы), использовался для живой проверки протокола.
  - `clear_old_discovery.py` — чистка старых retained MQTT discovery
    сообщений Home Assistant при переименовании кнопок.

## Как повторить / собрать

1. **Нужны 3 локальных файла (никогда не коммитятся, см. `.gitignore`):**
   - `secret/qr_code.txt` — полный текст QR-кода с корпуса привода (не сам
     QR-код картинкой, а то, во что он декодируется).
   - `secret/wifi_mqtt.txt` — `WIFI_SSID=`, `WIFI_PASSWORD=`, `MQTT_HOST=`
     (IP или `*.local` — тогда прошивка резолвит через mDNS), `MQTT_PORT=`,
     `MQTT_USER=`, `MQTT_PASSWORD=`.
2. `cd esp32 && pio run -t upload --upload-port COMx` — PlatformIO сам
   запустит `gen_secrets.py`, скачает NimBLE-Arduino/mbedTLS/PubSubClient.
3. Привод должен быть в режиме привязки BLE (см. грабли выше) для первой
   регистрации — кнопка **"Register new key"** появится в Home Assistant
   через MQTT discovery автоматически после первого подключения платы.
4. Остальные кнопки (Impuls/Light/1-2/Open/Close/Ventilation) работают
   сразу после успешной регистрации.
